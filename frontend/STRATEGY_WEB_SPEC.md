# E 部分 Web 策略展示与验收口径

## 1. 课程要求映射

本 Web 以低频沪深 A 股大盘/红利研究为产品场景，页面必须能够展示：

- 本组研究股票池，至少 10 个标的；
- 每个标的所属板块/行业与研究标签；
- 本组自己的策略规则；
- 策略使用的历史数据起止年份；
- 回测累计收益率（“这几年一共赚了多少个点”）；
- 最大回撤、Sharpe、交易次数等辅助指标；
- 智能化交易流程；
- 模拟盘账户、持仓、订单、成交。

## 2. 本组第一版策略

策略暂定名称：**大盘红利趋势低频策略**。

策略结构不是声称“单纯双均线就是本组原创策略”，而是将两个研究层次组合起来：

1. **股票池层**：从沪深 A 股大盘股中建立本组研究池，并重点研究红利风格标的；
2. **择时层**：使用日线 MA5 / MA20 交叉作为第一版可解释趋势信号；
3. **仓位层**：单次目标仓位 20%，单标的不超过 30%；
4. **执行层**：收盘形成信号，下一根 Bar 开盘模拟成交；
5. **风控层**：检查资金、持仓、订单价值和单标的仓位。

现有仓库已经提供双均线策略、账户、仓位、风控、OMS、模拟撮合和回测结果对象；E 只负责 Web 展示与 API 集成，不复制这些业务逻辑。

## 3. 历史数据口径

最终演示必须填写真实数据的起止年份，例如“2021—2025”。具体年份不能由前端编造，应以 A 数据模块提供的数据覆盖范围为准。

## 4. 收益口径

最终演示页面显示：

- 初始资金；
- 最终权益；
- 累计收益率；
- 年化收益率；
- 最大回撤；
- Sharpe；
- 交易次数。

收益率必须由 BacktestResult / 后端回测服务计算后返回。当前 Web V2 的“待回测”状态是刻意保留的，避免拿仓库里的单年示例 CSV 虚构多年收益。

## 5. 模拟盘口径

模拟盘不连接真实资金。页面启动后应调用后端 Simulation Mode，复用策略、风控、OMS、Broker Simulator 和 Account 逻辑。

## 6. 数据替换点

`src/mock/demo.js` 仅用于前端在后端尚未提供 API 时完成演示开发。正式答辩前必须替换为 A 提供的权威股票池、真实历史数据和后端回测结果。
